# 连接成功 = 隧道就绪 + Connectivity Probe

「连接成功」（含首次自动连接与 Repair 后验证）不得仅以系统 VPN 已连接判定，必须再经当前节点完成至少一次客户端 **Connectivity Probe** 成功。Probe 用于选节点加权与验收，**不是**流媒体/特定站点解锁检测，也不构成解锁 SLA。

**失败 UI（后继 ADR）：** 仅隧道就绪而探针失败 → **不得**宣称成功；Home 回 Idle + 短 toast（ADR **0059**）；**不**自动诊断（ADR **0060**）。

## Probe 形态（grill 2026-08-07 · A）

1. **单 HTTPS 可达：** 经当前节点对 **固定** HTTPS 端点发起请求；**TLS 握手成功且 HTTP 2xx**（或实现等价的「端点明确成功」）即 Probe 成功。  
2. **主目标 + 热备：** 配置 **主 URL** 与至少一个 **热备 URL**（仍属同一策略 A，非「多目标任一」产品叙事）。主失败则试备；用户 UI **不**展示目标列表或重试细节。  
3. **非 UI：** URL 为内部实现常数；上架前锁定。可先占位自控域名（如 `probe.routeva…`），部署后写入配置。  
4. **禁止：** 以 YouTube/Netflix 等用户内容站作默认成功标准；仅入口握手/隧道亮起算成功。

**Considered Options**
- 仅隧道就绪 → 假成功。  
- 用户指定站点验证 → 与解锁 SLA 混淆。  
- 2–3 目标「任一成功」作主叙事 → 实现与语义更重（未选）。  
- **选定：** 隧道 + 单 HTTPS Probe（主+热备）。

# 订阅刷新：默认自动 · 冷启动按日 · 用户可关

**Status：** accepted（2026-08-06 修订；取代「冷启动或连接前 + T=6h、无用户总闸」旧文）  
**Slug：** `0015-subscription-refresh-cold-start`（2026-08-06 自 `…-on-foreground` **改名**——正文从未允许回前台刷）

用户可在 **Settings › App** 用全局开关 **Auto-update subscription**（**默认开**）决定是否自动刷新订阅。开时：仅在**严格冷启动**、且 Active 距上次**成功**更新 ≥ **T=24h**、且 Active 有可复访远程源时，尝试整份再拉取（节点 + 可解析规则/策略组 + 有则元数据）。**不**在连接前、热启动/回前台或后台周期触发。成功安静落盘并记 Activity；Preferred 节点若失效则静默取消偏好，下次连接重选。自动失败完全安静且不覆盖旧配置。关开关后仅手动 **Update**（Subscriptions）与 Repair 重载。不可远程刷新的导入物自动路径 no-op；手动可说明无法更新。

**为何改：** 节点表陈旧会伤可用性，故默认自动且可关；连接前刷新拖慢主路径且问题多为「天」量级，故去掉连接前触发、T 从 6h 放宽到 24h；严格冷启动避免每次回前台拉订阅。

**Considered Options**
- 固定后台周期 → 耗电与 iOS 不可靠，明确不做。
- 连接前也刷 → 伤连接体验，否决。
- 仅手动、无自动 → 节点易陈旧，削弱 Table Stakes。
- 每订阅独立开关 → IA/实现过重，否决。
- 开关放 Subscriptions 列表 → 用户选 Settings › App 根页 Toggle 更易发现。
- **选定：** 全局默认开 + 冷启动 + T=24h + 手动 Update 并存。

# 首发采用 Thick Agent，但判定权仍在 Diagnostic Engine

在 Q1 已钉死「主证明点是自愈闭环」的前提下，产品决策仍选择首发交付 **Thick Agent**：开放自然语言、支持分流意图、云端为 Help 内可关增强，并作为信息架构中的主入口之一（用户可见 **Help**）。

**权衡：** 厚 Agent 抬高了交互与编排成本，也放大「AI 噱头」风险；换来的是更完整的故事与更高客单价感知，并与 Craft 目标一致（问诊体验要精致）。

**不妥协的约束：** 工具白名单；隐私（Token/凭证不上云）；无自由写配置；Repair 仅 Client-Fixable；无模型/无云时，连接、确定性诊断与白名单修复仍必须可用。衡量成功用自动修复率与连接稳定性，而非对话次数。

**云端策略（Q5 · 由 ADR 0042 修订）：** Cloud AI 为 Help 内增强，**非** Diagnostic Engine 替代大脑。**Help 默认开云、可关（opt-out）**；**无** 首次授权 modal；披露靠常驻信任条 + *How we use data*。关云后：快捷问题 / 本地或规则编排 / 模板解释 + 同一套工具仍可用。仅脱敏结构化上下文（Ephemeral）。**不**在 Settings 根页再挂一套开关。
